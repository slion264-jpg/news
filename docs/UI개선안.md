# 갈피 UI 개선안

목표는 두 가지다. **항목이 무엇인지 한눈에 잡히게 하고, 곁가지를 걷어내 핵심 메시지를 키운다.**
현재 화면을 측정한 결과와 그에 따른 개선안, 구현 범위를 적는다.

---

## 1. 진단

### 1.1 안내 문구가 본문 자리를 차지한다

홈 화면 텍스트 2,982자 중 **552자(19%)가 설명문**이다.

| 위치 | 분량 | 내용 |
|---|---|---|
| hero 문단 | 157자 | 수집 규모, φ 계산, 탐색 동선 설명 |
| sec-note 1 | 23자 | "보도량(기사 수) 기준 상위 다섯 개 토픽" |
| sec-note 2 | 85자 | **"대립지수 = 2 × min(찬성, 반대) + 0.25 × (찬성 + 반대)…"** |
| sec-note 3 | 41자 | "기간을 절반으로 갈라 기사 등장률 차이를…" |
| sec-note 4 | 35자 | "누르면 네트워크 탐색기에서…" |
| 푸터 | 211자 | 사이트 성격, 분류 방식, 정책 링크 |

**대립지수 산식이 홈 화면에 그대로 노출된다.** 방법론을 밝히는 태도는 이 사이트의 미덕이지만,
첫 화면에서 수식을 읽어야 할 이유는 없다. `method.html`이 이미 있고 그 안에 같은 설명이 있다.

### 1.2 대립 표현이 세 갈래로 흩어져 있다

| 화면 | 표현 방식 |
|---|---|
| 홈 · 핵심 이슈 | `pills` — "찬 5 · 반 3 · 제기 7" 배지 |
| 홈 · 찬반 대립 | `clash-bar` — 중앙축 기준 좌우 발산형 막대 (상위 6개만) |
| 토픽 목록 | `pills` 만 |
| 토픽 상세 | 의견 목록 (시각 요약 없음) |
| 네트워크 탐색기 | 텍스트 숫자 |

같은 개념을 네 가지 방식으로 그린다. 어느 것도 반복 학습되지 않는다.

### 1.3 대립 정보가 대부분 숨겨져 있다

토픽 **62개**의 구성이다.

| 구분 | 개수 | 비중 | 현재 노출 |
|---|---|---|---|
| 찬반 양쪽 있음 | 13 | 21% | 홈에 **6개만** |
| **한쪽 목소리만** | **29** | **47%** | 없음 |
| 의견 없음 | 20 | 32% | 없음 |

**한쪽 주장만 실린 토픽이 절반에 가까운데 화면 어디에도 그 사실이 드러나지 않는다.**
갈피가 잡아낼 수 있는 가장 강한 신호를 버리고 있는 셈이다.

### 1.4 모바일 대응이 거의 없다

`site.css` 194줄에 미디어쿼리가 3개뿐이고, 그중 2개는 네비게이션용이다. 실질적으로
`980px` 하나로 hero·duo·clash만 1열로 바꾼다. 나머지는 데스크톱 레이아웃 그대로다.

- `.rank-open` — `44px / 1fr / auto` 3열 그리드가 좁은 화면에서도 유지된다
- `.chips` — 24개가 줄바꿈되며 화면 여러 줄을 먹는다
- `.tbl .host` — 190px 고정 열
- 네비게이션 7개 항목이 모바일에서 두 줄을 차지한다

## 2. 설계 원칙

1. **하나의 개념에 하나의 도형.** 대립은 어디서든 같은 모양으로 그린다.
2. **설명은 필요한 곳에서 한 번만.** 홈에서 걷어내고 `분석 방법`으로 모은다. 화면에는
   해석에 꼭 필요한 최소 라벨만 남긴다.
3. **모바일을 기본으로 잡고 데스크톱으로 넓힌다.** 현재는 반대로 되어 있다.

## 3. (a) 안내 문구 정리

### 옮길 것

| 현재 | 이동처 |
|---|---|
| 대립지수 산식 | `method.html` 3장 (이미 유사 내용 있음) |
| 부상·소멸 계산 설명 | `method.html` 5장 (이미 있음, 홈에서 삭제) |
| hero의 φ 설명 문단 | `method.html` 링크 한 줄로 축약 |
| "누르면 네트워크에서 열립니다" | 마이크로카피로 축약 — 섹션 제목 옆 `→ 네트워크` |
| 푸터 2문단 | 1문단 + 링크 3개로 압축 |

### 남길 것

각 섹션에 **최대 한 줄, 20자 이내**의 라벨만 남긴다. 예: "보도량 기준", "의견 수 기준".

### 새로 만들 것 — 하단 안내 블록

푸터 바로 위에 접이식 안내를 둔다. 데스크톱에서는 3열, 모바일에서는 아코디언이다.

```
이 숫자들은 어떻게 나왔나  →  분석 방법
무엇을 싣고 무엇을 싣지 않나  →  이용 정책
직접 기간을 바꿔 보려면  →  네트워크 탐색기
```

홈에서 설명을 빼되 **길을 잃지 않게 하는 장치**다. 문구를 지우기만 하면 방법론의 투명성이
약해지므로, 접근 경로를 오히려 더 눈에 띄게 만든다.

## 4. (b) 메인 화면 재구성

### 현재

```
hero (제목 + 157자 설명 + KPI 4 + CTA + 일자 스트립)
오늘의 낱말 배너
핵심 이슈 TOP 5          (보도량 기준)
찬반 대립이 치열한 이슈    (6개)
구간 전반 대 후반          (부상 7 · 소멸 7)
가장 많이 등장한 키워드    (24개)
```

### 제안

```
hero (제목 + KPI 4 + CTA)                     ← 설명문 제거
오늘의 키워드            상위 12개              ← 위로 올림, 24 → 12
가장 팽팽한 이슈          5개 · 대립 바 강조     ← 핵심
한쪽 목소리만 실린 이슈    4개 · 신규            ← 숨어 있던 29개를 드러냄
보도량이 가장 많은 이슈    5개                   ← 기존 '핵심 이슈'
네트워크 · 오늘의 낱말 진입
하단 안내 블록
```

바뀌는 점 세 가지다.

**'부상·소멸' 섹션을 홈에서 뺀다.** 네트워크 탐색기의 `rankHTML()`이 같은 내용을 이미
보여주고, 기간을 바꿔 가며 보는 쪽이 훨씬 유용하다. 홈에서는 중복이다.

**대립을 보도량보다 위에 둔다.** 보도량 순위는 어느 뉴스 사이트에나 있다. 갈피만 할 수 있는
것은 찬반 구조이므로 첫 화면의 주인공을 바꾼다.

**'한쪽 목소리만' 섹션을 신설한다.** ground.news의 Blindspot이 "한쪽 진영만 보도한 뉴스"를
따로 모아 보여주는 것과 같은 발상이다. 갈피에서는 진영이 아니라 **사안에 대한 찬반**이므로
"반론이 실리지 않은 이슈"가 된다. 29개나 있다.

## 5. (c) 대립 표시 컴포넌트

가장 중요한 항목이다. **하나의 컴포넌트를 만들어 모든 화면에서 재사용한다.**

### 5.1 형태

100% 누적 가로 막대. 왼쪽부터 반대 · 제기 · 찬성 순서로 고정한다.

```
반대 3 ████████░░░░░░░░░░░░░░░░ 찬성 5
       ▓▓▓▓▓▓ 제기 7
```

- 색은 기존 변수를 그대로 쓴다 — `--con` 반대, `--neu` 제기, `--pro` 찬성
- 막대 폭은 **비율**, 옆의 숫자는 **규모**를 나타낸다. 두 정보를 분리해 담는다
- 높이 10px, 모서리 2px. 모바일에서도 같은 크기를 유지한다

### 5.2 상태 배지

막대 왼쪽에 한 단어 배지를 붙인다. 이것이 "인지가 명확해야 한다"는 요구에 직접 답한다.

| 배지 | 조건 | 색 |
|---|---|---|
| **팽팽** | 찬반 양쪽 존재, `min/max ≥ 0.4` | 강조색 |
| **기울어짐** | 찬반 양쪽 존재, `min/max < 0.4` | 중간 |
| **한쪽만** | 찬성 또는 반대 한쪽만 존재 | 경고색 |
| **문제제기만** | 제기만 존재 | 회색 |
| **의견 없음** | 의견 0건 | 흐린 회색 |

배지 문구는 그 자체로 뜻이 통해야 하며, 산식을 알 필요가 없어야 한다.

### 5.3 적용 위치

| 화면 | 적용 |
|---|---|
| 홈 · 팽팽한 이슈 | 막대 + 배지 + 숫자 (큰 크기) |
| 홈 · 한쪽 목소리만 | 배지 강조 + 막대 |
| 홈 · 보도량 TOP5 | 막대만 (작은 크기), `pills` 대체 |
| 토픽 목록 카드 | 막대 + 배지, `pills` 대체 |
| 토픽 상세 헤더 | 막대 + 배지 + 의견 수 |
| 네트워크 탐색기 토픽 목록 | 막대 (작은 크기) |

`pills`(찬 5 / 반 3 / 제기 7)와 `clash-bar`(발산형)는 **삭제하고 이것으로 통일한다.**

### 5.4 주의 — 정치 성향으로 읽히지 않게 한다

ground.news의 막대는 **매체의 정치 성향**(좌–중–우)을 나타낸다. 갈피의 막대는
**사안에 대한 발언자의 입장**이다. 형태가 비슷해 오독 위험이 있다.

- 좌우 배치를 정치 스펙트럼처럼 보이지 않게, **반대를 왼쪽·찬성을 오른쪽**으로 고정하고
  중앙축(현재 `clash-axis`)을 없앤다. 중앙축은 '중도'를 연상시킨다
- 색에 정당색(파랑·빨강)을 쓰지 않는다. 현재의 초록–주황–적색 계열을 유지한다
- 막대 옆에 `사안에 대한 입장` 이라는 짧은 라벨을 한 번 노출한다

`content.py`의 기존 문구 — "'찬성/반대'는 해당 사안에 대한 태도를 뜻하며, 특정 정치 세력에
대한 지지를 뜻하지 않습니다" — 를 `분석 방법`에서 더 눈에 띄게 배치한다.

## 6. (d) 모바일 레이아웃

### 브레이크포인트

| 폭 | 처리 |
|---|---|
| ~1180px | 데스크톱 기본 |
| 900px | hero 1열, 섹션 여백 축소(54px → 32px) |
| 620px | rank·clash 카드형 전환, 네비 축약, 폰트 스케일 |
| 380px | 최소 대응 |

### 항목별

**네비게이션** — 7개는 모바일에서 두 줄을 먹는다. `홈 · 네트워크 · 토픽 · 기사` 4개만 남기고
`오늘의 낱말 · 분석 방법 · 이용 정책`은 `⋯` 메뉴로 접는다. 오늘의 낱말은 홈 배너로 이미
접근 가능하다.

**`.rank-open`** — `44px / 1fr / auto` 3열을 620px 이하에서 1열로 바꾼다. 순위 번호는
제목 앞에 인라인으로, 기사 수는 메타 줄로 내린다.

**`.chips`** — 24개 → 12개로 줄이고, 모바일에서는 2줄까지만 노출한 뒤 `+더보기`.

**터치 영역** — 현재 `.chip` 높이가 약 26px이다. 모바일에서 최소 44px를 확보한다.

**타이포** — `hero h1` 44px → 33px(980px) → **26px(620px)** 로 한 단계 더 내린다.
`.rank-title` 17px → 15.5px.

**표** — `.tbl .host` 190px 고정 열을 모바일에서 숨기고 매체명을 제목 아래 메타로 옮긴다.

## 7. 구현 범위

건드리는 파일은 넷이다. 데이터(`data.json`)와 분석 로직은 **전혀 손대지 않는다.**

| 파일 | 작업 |
|---|---|
| `assets/site.css` | 대립 바 컴포넌트 추가, `pills`·`clash-*` 삭제, 미디어쿼리 재작성 |
| `build.py` | `pills()` → `stancebar()` 교체, `build_index()` 섹션 재구성, `build_topics()`·`build_topic()` 반영 |
| `content.py` | 홈에서 뺀 설명을 `method.html`로 흡수, 찬반 주의 문구 강조 |
| `explore.tpl.html` | `topicHTML()`에 대립 바 적용 |

### 순서

1. **대립 바 컴포넌트** — CSS + `build.py`의 헬퍼 함수. 기존 `pills` 자리에 그대로 교체하면
   전 화면에 한 번에 반영된다. 여기서 효과의 절반이 나온다.
2. **홈 재구성** — 섹션 순서 변경, '한쪽 목소리만' 신설, '부상·소멸' 제거
3. **안내 문구 이동** — `content.py` 보강, 하단 안내 블록
4. **모바일** — 미디어쿼리 재작성, 네비 축약

각 단계마다 `python3 build.py`로 생성이 통과하는지 확인하고, 데스크톱·모바일 폭에서
눈으로 검증한다.

### 되돌리기

전 단계가 표현 계층에만 머무르므로 `git revert` 한 번으로 원복된다. 데이터와 분석 결과는
영향을 받지 않는다.

## 8. 논의가 필요한 지점

1. **'한쪽 목소리만' 이라는 이름.** 사실 서술이지만 매체를 탓하는 뉘앙스로 읽힐 수 있다.
   `반론이 실리지 않은 이슈`, `한쪽 주장만` 등 대안이 있다.
2. **'부상·소멸' 홈에서 제거.** 네트워크에 있으니 중복이라 보았으나, 홈에서 즐겨 보셨다면
   유지할 수 있다.
3. **키워드 24개 → 12개.** 상위 12개면 충분한지, 아니면 모바일에서만 줄일지.
4. **네비 축약.** `분석 방법`을 모바일 상단에서 빼는 것이 방법론 투명성과 충돌하는지.
   하단 안내 블록이 이를 보완한다고 보았다.
